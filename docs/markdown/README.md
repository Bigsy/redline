# Rendered Markdown verification

The synthetic [before](../../testdata/markdown/before.md) and
[after](../../testdata/markdown/after.md) demo covers metadata, prose, emphasis, links,
blockquotes, tables, task lists, and fenced code. The feature uses pinned `marked@18.0.14`
inside the existing worker bundle, followed by Redline's sanitizer and `redline-engine@0.1.0`.
Neither sibling MilkJ nor the local engine checkout is a build dependency.

## Visual inspection

Chromium screenshots were inspected in both themes, including the lower part of the document:

- [Light](rendered-light.png), [light tables/lists/code](rendered-light-lower.png)
- [Dark](rendered-dark.png), [dark tables/lists/code](rendered-dark-lower.png)

The screenshots show separate escaped metadata, readable inline prose changes, table revisions,
disabled task checkboxes, and complete code-block replacements. Document surfaces follow the
IDE theme, including the gutters. Metadata has inline edits with preserved whitespace; code blocks
retain complete before/after replacements with a specific explanation. Mermaid, math, syntax highlighting, editing, and merge
controls are outside scope.

The sandbox was restarted after the final plugin/resource changes. See
[packaged JCEF results](jcef-results.json), [light](jcef-light.png) / [dark](jcef-dark.png)
screenshots, and [package audit](package-audit.json).

The 2026.2.1 follow-up adds the separate bundled JCEF plugin to Gradle's classpath for 2026.2+
targets, matching the existing optional runtime dependency. Without that build dependency,
unresolved JCEF imports caused secondary `IntRef.set` compiler errors. The default target remains
2024.1; `./gradlew runIde -PplatformVersion=2026.2.1` also works.

The precision follow-up removes only formatting whitespace generated by Marked between table
rows/cells. It retains Marked's inline cell parser and leaves raw reviewed HTML unchanged.
Frontmatter uses a whitespace-preserving text container, allowing inline value edits instead
of atomic `pre` replacement. The demo now has one coarse operation (its fenced code block),
instead of three (metadata, entire table body, and code). Original and Final still reconstruct
the prepared inputs exactly. Other actual comparison fallbacks retain an explicit notice.

Browser tests serve the built plugin assets and use the actual conversion/comparison workers,
with intercepted document routes. They also cover cancellation, timeout, unavailable workers,
oversized input, superseding refresh with at most one active worker, and hostile identical/added
fallbacks (scripts, handlers, refresh, marker spoofing, and remote resources).
Kotlin tests cover file types, extension variants, revision metadata without live files,
added/deleted content, mixed/binary rejection, session format persistence, MIME and URL routing.

Native Swing toolbar Swap Sides and actual IDE Document/VFS edits were not operated in this
session: the available computer-use surface was disabled. Session update/swap behavior is covered
by Kotlin tests and refresh by browser/JCEF tests; revision-history and Local Changes entry points
are covered by platform-content detection tests, rather than native UI interaction.

## Reproduce

```sh
cd frontend
CI=true pnpm run typecheck
CI=true pnpm run test
CI=true pnpm run build
CI=true pnpm run test:e2e
cd ..
./gradlew check buildPlugin
./gradlew runIde --args="diff testdata/markdown/before.md testdata/markdown/after.md"
```

Select Redline in the viewer switcher. For the optional packaged JCEF smoke script, launch the
sandbox with `JAVA_TOOL_OPTIONS=-Dide.browser.jcef.debug.port=9223`, then run
`node bench/markdown-jcef.mjs` from `frontend/`. That script verifies the actual packaged worker,
modes, navigation bridge, find, theme, and shell refresh; injected refresh payloads do not prove
native Document/VFS edit notifications or native Swap Sides toolbar dispatch.

No version bump, commit, tag, publication, or sibling-repository change is part of this work.
